Workfront Fusion Scenarios

Architectural boundary: A marketer's form submission creates a Workfront Issue/Request (intake record only). Fusion S1 validates and routes it; Fusion S2 transfers all intake data into the Marketer Project task forms. From that point on, all Adobe I/O actions, build operations, and validation logic run exclusively on Workfront Projects and Tasks — never directly on the Workfront Issue/Request.

Scenario Name Trigger Action
S1 Intake Request Processing New request submitted (Workfront Issue created) Validates & routes request; intake data stays in the Issue at this stage
S2 Marketer Project Creation Request validated by S1 Creates marketer project from template; transfers all intake Issue data into project task forms — this is the boundary after which all Adobe I/O, build, and validation operations run on project/task data
S3 Task Change Watcher Marketer task updated Updates content.js with latest data
S4 Email Governance Watch Governance task complete Triggers sync object generation
S5 Ops Project Creation Governance approved Creates ops project with region/CTA routing
S6 Sync Object & SnapLogic Build task complete Builds MCZ payload, invokes SnapLogic API
S7 Response Processing SnapLogic response received Updates projects with MCZ links, activates QA
