Workfront Fusion Scenarios

Architectural boundary: A marketer's form submission creates a Workfront Issue/Request (intake record only). Fusion S1 validates and routes it; Fusion S2 creates the Unified Campaign Project (APAC or AMER template) and transfers all intake data into project task forms. From that point on, all Adobe I/O actions, build operations, and validation logic run exclusively on Workfront Projects and Tasks — never directly on the Workfront Issue/Request.

Scenario Name Trigger Action
S1 Intake Request Processing New request submitted (Workfront Issue created) Validates & routes request; intake data stays in the Issue at this stage
S2 Unified Project Creation Request validated by S1 Creates unified campaign project using region-based template (APAC or AMER); transfers all intake data into project task forms; sets Multi CTA Build task duration +1 day if applicable; adds SFDC Tracking task if SFDC flag set — boundary after which all Adobe I/O, build, and validation operations run on project/task data
S3 Task Change Watcher Unified project task updated Updates content.js with latest data; re-runs overview-build and validation-summary
S4 Email Governance Watch Email Governance Task marked complete (Phase 1) Activates Phase 2 (Operations) tasks within the unified project; writes ops-level overview via Adobe I/O overview-summary-ops
S6 Sync Object & SnapLogic Build task complete Builds MCZ payload, invokes SnapLogic API
S7 Response Processing SnapLogic response received Updates unified project with MCZ links, activates QA task
